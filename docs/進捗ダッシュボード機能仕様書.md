# プロジェクト進捗管理画面 機能仕様書

## 0. 本書について

- 本書は画面ごとの表示項目・操作・入力チェック・メッセージ文言・状態遷移を、実装・テストにそのまま利用できる粒度で定義する。要件の根拠は [要件定義書](./進捗ダッシュボード要件定義書.md)、内部実装(型・関数・コンポーネント)は [詳細設計書](./進捗ダッシュボード詳細設計書.md)を参照する。
- 画面IDは基本設計書・詳細設計書と共通(SCR-01〜05)。
- メッセージ文言は既存Todo機能([src/components/todo/todo-view.tsx](../src/components/todo/todo-view.tsx))の「〜しました」「〜に失敗しました」というトーン・文体に合わせている。

## 1. 共通仕様

### 1.1 ヘッダーナビゲーション

[src/components/layout/header.tsx](../src/components/layout/header.tsx)の`mainNavItems`を以下のとおり変更する。

| ラベル | href | 変更前 | 変更後 |
| --- | --- | --- | --- |
| ダッシュボード | `/dashboard` | `active`未指定(無効・ツールチップ「近日公開予定です」) | `active: true`相当(通常リンク化) |
| プロジェクト | `/projects` | 同上 | 同上 |

Todo・カレンダーの各ナビ項目は本機能の対象外のため変更しない。

### 1.2 プロジェクト切替(`ProjectSwitcher`)

- 配置: `/dashboard`ページ上部(タブの上、プロジェクト完了率サマリの左)。
- 選択候補: アーカイブされておらず、かつ削除されていないプロジェクトのみ(`listSwitchableProjectsAction`)。
- 候補が0件の場合: セレクトの代わりに「プロジェクトがありません」というテキストと「プロジェクトを作成」ボタン(`/projects`へのリンク)を表示する。
- 選択変更時: 即座にURLクエリ`?project=<id>`を書き換え、選択中プロジェクトのデータを再取得して画面全体(現在表示中のタブ)を再描画する。タブ切替は保持する。
- URLの`project`パラメータが存在するがそのプロジェクトが存在しない/アーカイブ済み/削除済みの場合: 候補の先頭(作成日時が最も新しいもの)へ自動的にフォールバックする。

### 1.3 メッセージ表示規約

- 成功時は`toast.success`、失敗時は`toast.error`(既存Todo機能踏襲)。
- 「元に戻す(Undo)」操作を提供する場合は、成功トーストの`action`にボタンを埋め込む(例: 成果物削除時)。本機能で元に戻す操作を提供するのは「プロジェクトの論理削除」のみ(ゴミ箱からの復元操作で代替可能なため、削除直後のトースト上にUndoは設けない。理由: プロジェクト削除は確認ダイアログを経由する重い操作であり、既存Todo機能の「タスク削除」ほど頻発しないため)。
- 業務ルールエラー(プロジェクト名重複、成果物種類の使用中削除)は、詳細設計書 2.5節の`ActionResult`を分岐し、サーバーから返された具体的な文言をそのまま`toast.error`に表示する。

### 1.4 ステータス表示一覧

| 区分 | 値 | 表示ラベル | バッジ色 |
| --- | --- | --- | --- |
| 成果物ステータス | `not_started` | 未着手 | グレー |
| | `in_progress` | 進行中 | 青 |
| | `on_hold` | 保留 | 黄 |
| | `in_review` | レビュー中 | 紫 |
| | `done` | 完了 | 緑 |
| セル/機能行 集約ステータス | `not_applicable` | 対象外(-) | 淡グレー |
| | `partially_delayed` | 一部遅延 | 赤(強調) |
| | `done` | 完了 | 緑 |
| | `not_started` | 未着手 | グレー |
| | `in_progress` | 進行中 | 青 |

## 2. SCR-01 全体進捗ビュー

### 2.1 前提条件

- 選択中プロジェクトに`Phase`・`Feature`が1件も無い場合、マトリクス表は表示できない。「工程・機能が未登録です。まず工程・機能を登録してください」という空状態を表示し、工程・機能の追加UIへの導線を出す。

### 2.2 表示項目一覧

| 項目 | データソース | 表示形式 | 空値時 |
| --- | --- | --- | --- |
| プロジェクト全体完了率 | `projectCompletionSummary` | 「全体完了率: 42% (21/50)」 | 成果物0件時「対象データがありません」 |
| 工程別完了率(列ヘッダー) | `phaseCompletionSummary` | 「基本設計: 12/20 成果物 完了」 | セル同様「対象外」 |
| マトリクス行 | `Feature`(`order`昇順) | 機能名 | - |
| マトリクス列 | `Phase`(`order`昇順) | 工程名 | - |
| セル | `aggregateCellStatus` | バッジ+件数(例: 「進行中(2/5)」) | 0件時「-」(`not_applicable`) |
| 成果物種類パレット | `DeliverableType`(プロジェクト固有、`order`昇順) | バッジ一覧(横スクロール) | 0件時「成果物種類が未登録です」+マスタ管理への導線 |

### 2.3 操作仕様

| # | 操作 | 事前条件 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- | --- |
| 1 | セルをクリック | - | `CellDetailPanel`を対象セルの内容でモーダル表示 | - | - |
| 2 | パレットの成果物種類をセルへドラッグ&ドロップ | ドロップ先が有効なセル | 2.4節の確認フロー通過後`createDeliverableFromDropAction`実行 | トースト「「{機能名} {種類名}」を追加しました」。マトリクス即時再集計 | トースト「追加に失敗しました」 |
| 3 | セル詳細パネルのプルダウンから成果物種類を選択して追加 | - | 操作2と同じ確認フロー・Actionを経由(D&D代替) | 同上 | 同上 |
| 4 | グリッド内でステータスを変更 | - | `updateDeliverableAction(id, { status })` | トースト「ステータスを更新しました」 | トースト「更新に失敗しました」 |
| 5 | グリッド内で成果物を編集(名称/担当者/日付/メモ) | 入力値が2.4節のバリデーションを満たす | 「保存」ボタン押下で`updateDeliverableAction` | トースト「保存しました」 | トースト「保存に失敗しました」 |
| 6 | グリッド内で成果物を削除 | - | `AlertDialog`「この成果物を削除しますか?この操作は元に戻せません」→OKで`deleteDeliverableAction` | トースト「「{成果物名}」を削除しました」 | トースト「削除に失敗しました」 |
| 7 | 機能/工程/成果物種類マスタの追加・編集・削除 | 6章参照 | 6章参照 | 6章参照 | 6章参照 |

### 2.4 バリデーション・確認ダイアログ

| ケース | タイミング | 表示 | OK時 | キャンセル時 |
| --- | --- | --- | --- | --- |
| ドロップ先工程がパレット項目の想定工程と不一致 | ドロップ直後(Action呼び出し前) | 確認ダイアログ「「{種類名}」の想定工程は「{想定工程名}」ですが、「{ドロップ先工程名}」に追加しようとしています。追加しますか?」 | 次の確認(重複チェック)へ進む、または直接追加 | 追加を中止(何も変更しない) |
| 同一セルに同一種類が既に存在 | ドロップ直後(工程不一致確認の後) | 確認ダイアログ「同じ種類の成果物が既に存在します。追加しますか?」 | 追加を実行 | 追加を中止 |
| 成果物名が空 | 保存押下時 | 保存ボタンを`disabled`にし、入力欄に「成果物名を入力してください」を表示(既存`isTitleValid`パターン踏襲) | - | - |
| 実績完了日 < 実績開始日、または予定完了日 < 予定開始日 | 入力変更時 | 「終了日は開始日以降の日付にしてください」(既存`isDateRangeInvalid`のメッセージを踏襲) | - | - |

### 2.5 セル詳細パネル(グリッド)仕様

- 各成果物カードに表示: 成果物名(編集可)、ステータスピッカー(5値)、担当者(テキスト入力)、予定開始日/予定完了日、実績開始日/実績完了日、進捗率(ステータスが`in_progress`/`on_hold`/`in_review`のときのみスライダー表示。既存`TaskDetailPanel`のプログレス表示条件踏襲)、メモ、保存ボタン(dirty時のみ活性)、削除アイコン。
- カードは`plannedEndDate`超過かつ未完了の場合、カード全体に赤系の枠線を付けて強調する(一覧内でも遅延が視認できるように)。
- パネル下部に「＋成果物を追加」(プルダウンによる代替追加。2.3節 操作3)を常設する。

## 3. SCR-02 スケジュール(ガント)ビュー

### 3.1 前提条件

- 全体進捗ビューと同一プロジェクトの`Feature`/`Deliverable`データを用いる。`Feature`が0件の場合は2.1節と同じ空状態を表示する。

### 3.2 表示項目一覧

| 項目 | データソース | 表示形式 |
| --- | --- | --- |
| 表示単位切替 | クライアントstate | セグメントボタン「週/月/四半期」 |
| 機能フィルタ / 工程フィルタ | クライアントstate | セレクト(「全て」を既定値とする) |
| 機能行(折りたたみ時) | `Feature` | 機能名+遅延件数バッジ(例: 「発注機能(遅延2件)」。0件時はバッジ非表示) |
| 成果物行(展開時) | `Deliverable` | 成果物名+予定バー+実績バー |
| 予定バー | `plannedStartDate`〜`plannedEndDate` | 半透明の背景バー。日付未設定の場合はバー非表示、行に「予定日未設定」を薄字で表示 |
| 実績バー | `actualStartDate`〜`actualEndDate`または`progress` | ステータス色で塗りつぶし。遅延中(`isDelayed`)は赤枠で強調 |

### 3.3 操作仕様

| # | 操作 | 処理 | 備考 |
| --- | --- | --- | --- |
| 1 | 表示単位切替 | クライアント側で列幅・ラベルを再計算 | 再フェッチなし |
| 2 | 機能行クリック | `expandedFeatureIds`をtoggle | 初期状態は全機能が折りたたみ(要件定義書 9章確定事項) |
| 3 | 機能/工程フィルタ変更 | クライアント側でdeliverables配列をfilter | 再フェッチなし |
| 4 | バークリック | `Popover`で「予定: {開始}〜{終了}」「実績: {開始}〜{終了 or 進行中}」「遅延: {N}日」(遅延時のみ)を表示 | - |

### 3.4 画面状態

- 予定日・実績日が両方とも未設定の成果物は、バーを描画せず行のみ表示する(0件と誤認されないよう成果物名は必ず表示する)。

## 4. SCR-03 設計書QA機能

### 4.1 前提条件

- プロジェクトの`designDocFolderPath`が未設定(空文字)の場合、QAタブ全体を「設計書フォルダが未設定です。プロジェクト管理画面から設定してください」という案内に差し替え、チャット入力を無効化する。

### 4.2 表示項目一覧

| 項目 | データソース | 表示形式 |
| --- | --- | --- |
| 再取り込みボタン | - | ボタン(実行中は`disabled`+スピナーアイコン+文言「取り込み中…」) |
| 最終取り込み日時 | `listDesignDocumentsAction().lastScannedAt` | 「最終取り込み: 2026-09-05 10:20」。未実行時「未実行」 |
| 未取り込み警告 | `pendingCount` | `pendingCount > 0`の場合のみ黄色警告バー「未取り込み/インデックス未反映の設計書が{N}件あります」 |
| チャット履歴(本文) | `askQuestionAction`/`listQaHistoryAction` | 質問・回答を吹き出し形式で表示 |
| 参照元 | `answer.sources` | 回答直下にチップ形式「{ドキュメント名} > {セクション名}」を複数表示 |
| 質問入力欄 | クライアントstate | テキストエリア+送信ボタン(空文字時`disabled`) |
| 履歴一覧(サイド) | `listQaHistoryAction` | 質問文+日時のリスト、クリックで本文にスクロール/再表示 |

### 4.3 操作仕様

| # | 操作 | 事前条件 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- | --- |
| 1 | 「再取り込み」押下 | 実行中でない | `rescanDesignDocumentsAction` | トースト「取り込みが完了しました(追加{added}件・更新{updated}件・失敗{failed}件)」。`failed > 0`の場合は`toast.warning`相当(赤字ではなく黄字)で失敗ファイル名を併記 | トースト「取り込みに失敗しました」(想定外の例外時のみ。ファイル単位の失敗は上記に含める) |
| 2 | 質問送信 | 入力欄が空でない、かつ`asking`でない | `askQuestionAction` | チャットに回答+参照元を表示。入力欄クリア | トースト「回答の生成に失敗しました」。チャットにエラー行「回答を生成できませんでした。再度お試しください」を残す |
| 3 | 参照元チップをクリック | - | 該当`DesignDocument.filePath`の該当箇所を新規タブ/プレビューで開く(拡張子ごとの遷移方式は詳細設計書 5.1節・8章の残課題) | - | ファイルが見つからない場合「参照元のファイルが見つかりませんでした」 |
| 4 | 履歴一覧から過去の質問をクリック | - | 対象の質問・回答・参照元をチャット本文にスクロール表示(再送信はしない) | - | - |

### 4.4 画面状態

| 状態 | 表示 |
| --- | --- |
| 初期表示(履歴0件) | 「まだ質問がありません。設計書について質問してみましょう」という空状態+入力欄 |
| 回答生成中 | 直近の質問吹き出しの下に「回答を生成しています…」のローディング表示(要件定義書 6章「可用性」対応) |
| 取り込み中 | ボタン`disabled`+画面上部にプログレス表示(進捗率までは出さず、不定形スピナーでよい) |

## 6. マスタ管理共通仕様

工程(`Phase`)・機能(`Feature`)・成果物種類(`DeliverableType`/`GlobalDeliverableType`)は、権限分離を設けず利用者全員が編集可能(要件定義書 4章)。

### 6.1 工程・機能マスタ(全体進捗ビューからアクセス)

| # | 操作 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | 追加 | 名称入力(空文字不可)→`createPhaseAction`/`createFeatureAction` | トースト「「{name}」を追加しました」 | トースト「追加に失敗しました」 |
| 2 | 名称編集 | インライン編集→`updatePhaseAction`/`updateFeatureAction` | トースト「更新しました」 | トースト「更新に失敗しました」 |
| 3 | 並び替え | ドラッグでの並び替え(D&D、`order`更新) | 即時反映(トーストなし、既存Todo機能の並び替え相当の軽操作として扱う) | トースト「並び替えに失敗しました」 |
| 4 | 削除 | `AlertDialog`「「{name}」を削除しますか?この工程/機能に紐づく成果物もすべて削除されます」→OKで`deletePhaseAction`/`deleteFeatureAction` | トースト「「{name}」を削除しました」 | トースト「削除に失敗しました」 |

### 6.2 成果物種類マスタ(プロジェクト固有・`DeliverableType`)

| # | 操作 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | 追加 | 名称+想定工程(セレクト、任意)入力→`createDeliverableTypeAction` | トースト「「{name}」を追加しました」 | トースト「追加に失敗しました」 |
| 2 | 編集(名称・想定工程) | `updateDeliverableTypeAction` | トースト「更新しました」。**使用中(成果物が紐づいている)でも常に編集可能** | トースト「更新に失敗しました」 |
| 3 | 削除 | `deleteDeliverableTypeAction` | トースト「「{name}」を削除しました」 | 使用中の場合: `AlertDialog`または`toast.error`で「この種類を使用している成果物が{count}件あるため削除できません」を表示し削除不可(要件定義書 5.1節)。削除ボタン自体も`deliverableCount > 0`の間は視覚的に警告アイコンを添えるが、非活性にはせず押下時にエラーで案内する(押せない理由がわからない状態を避けるため) |

### 6.3 共通成果物種類マスタ(`GlobalDeliverableType`、プロジェクト管理画面)

| # | 操作 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | 追加 | 名称+想定工程名(自由入力テキスト。共通マスタは`Phase`実体を持たないため文字列。詳細設計書1.1節参照)→`createGlobalDeliverableTypeAction` | トースト「追加しました」 | トースト「追加に失敗しました」 |
| 2 | 編集 | `updateGlobalDeliverableTypeAction`。**既存プロジェクトの`DeliverableType`には遡って影響しない**旨をフォーム内に注記表示 | トースト「更新しました」 | トースト「更新に失敗しました」 |
| 3 | 削除 | `deleteGlobalDeliverableTypeAction`(使用中チェック不要、常に削除可) | トースト「削除しました」 | トースト「削除に失敗しました」 |

## 8. 受け入れ基準(画面別チェックリスト)

### SCR-01 全体進捗ビュー
- [ ] セル内に1件でも遅延成果物があれば、他がすべて完了でもセルが「一部遅延」表示になる
- [ ] セル内成果物0件は「-(対象外)」と表示され、完了率の分母・分子に含まれない
- [ ] 工程不一致のドロップで警告が出て、キャンセルすると成果物が追加されない
- [ ] 同一セルへの同一種類の再ドロップで確認が出て、OKで2件目が追加される
- [ ] D&Dできない操作(プルダウン追加)でも同じ確認フローを通る

### SCR-02 ガントビュー
- [ ] 初期表示で成果物行がすべて折りたたまれている
- [ ] `plannedEndDate`を1日でも超過し未完了の成果物バーが赤強調される(猶予日数なし)
- [ ] 機能行の「遅延N件」が配下成果物の`isDelayed`件数と一致する

### SCR-03 設計書QA
- [ ] 回答に必ず参照元(ドキュメント名+セクション)が1件以上併記される(根拠なしで回答しない)
- [ ] 未取り込みファイルがある間は警告が表示され続ける
- [ ] 再取り込み実行中は連打してもリクエストが多重発行されない(ボタン`disabled`)

### SCR-04/05 プロジェクト管理
- [ ] 削除済み(ゴミ箱内)のプロジェクトと同名では新規作成できない
- [ ] 30日経過後もプロジェクトはゴミ箱に残り続け、自動削除されない
- [ ] 復元時、稼働中に同名プロジェクトがあれば復元がエラーになる
- [ ] 共通成果物種類マスタの変更が既存プロジェクトの`DeliverableType`に影響しない
