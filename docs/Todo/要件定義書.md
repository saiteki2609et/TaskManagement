# Todo機能 要件定義書

## 0. 本書について

- 本書は既に実装済みの`/todo`画面(Todo機能)を対象に、実装内容から逆引きで要件を整理した文書である。進捗ダッシュボード機能の4文書([要件定義書](../進捗ダッシュボード/要件定義書.md)等)とは異なり、実装に先立って書かれたものではなく、**現状の実装が満たしている要件を記録する**ことを目的とする。今後の変更提案・仕様確認のベースラインとして用いる。
- 対象コード: [src/app/todo](../../src/app/todo)、[src/components/todo/](../../src/components/todo/)、[src/lib/actions/tasks.ts](../../src/lib/actions/tasks.ts)、[src/lib/tasks/](../../src/lib/tasks/)。

## 1. 目的・背景

- 個人〜小規模チームが、日々のタスクを**親子関係を持つ階層構造**で管理できる画面を提供する。
- 進捗ダッシュボード機能(`Project`配下の工程・成果物管理)とは独立した機能であり、両者はデータ・画面ともに一切連携しない。

## 2. スコープ

### 2.1 対象(In Scope)

1. タスクの階層管理(親タスク・サブタスクの無制限ネスト)
2. タスクのステータス(未着手/進行中/完了)・優先度(高/中/低/未設定)・進捗率・期間(開始日〜終了日)・メモ・タグの管理
3. テキスト入力による複数タスクの一括追加(インデントで階層を表現)
4. JSON/CSV形式でのエクスポート・インポート
5. 検索(タスク名・メモ・タグ)、ステータス・優先度・期限によるフィルタ、並び替え(追加順/優先度順)
6. 同一階層内でのドラッグ&ドロップによる並び替え
7. タスクの削除(論理削除)・ゴミ箱からの復元・完全削除
8. タスクの複製(サブタスクを含めた複製)

### 2.2 対象外(Out of Scope)

- 進捗ダッシュボード機能(`Project`・工程・成果物等)とのデータ連携
- 複数ユーザー間での共有・権限管理(本アプリ全体がロール分けを持たない単一ユーザー前提)
- タスクの期限に対する通知・リマインダー機能
- 添付ファイル・コメント機能
- 親タスクを跨いだドラッグ&ドロップでの再配置(同一階層内の並び替えのみ対応)

## 3. 用語定義

| 用語 | 定義 |
| --- | --- |
| タスク | Todo機能で管理する作業単位。`title`・`status`・`priority`・`memo`・`startDate`/`endDate`・`progress`・`tags`を持つ |
| サブタスク | あるタスクの子として登録されたタスク。ネスト段数に上限は無い |
| リーフタスク | 子を持たないタスク(サブタスクが1件もないタスク)。進捗集計(4章)はリーフタスク単位で行う |
| ステータス | タスクの状態。「未着手」「進行中」「完了」の3種 |
| 優先度 | 「高」「中」「低」「未設定」の4段階 |
| 並び替え(sortMode) | 一覧の表示順。「追加順」(`order`フィールドどおり)と「優先度順」の2種 |
| ゴミ箱 | 論理削除(`deletedAt`セット)されたタスクの一覧。復元または完全削除ができる |

## 4. 利用者・利用シーン

- 想定利用者: 本アプリの利用者本人(単一ユーザー、権限分離なし)。
- 利用シーン: 日次のタスク管理、プロジェクトに紐づかない個人的なタスクの階層的な整理、既存タスクリストの一括取り込み(他ツールからのCSV/JSONエクスポートの流用等)。

## 5. 機能要件

### 5.1 タスクの階層管理

- タスクは親子関係を持ち、ネスト段数に制限はない。
- 各タスク行には子タスクの展開/折りたたみ状態を持つ(初期状態は全て折りたたみ)。「すべて展開」「すべて折りたたむ」ボタン、および行単位の「子タスクをすべて展開/折りたたむ」操作を提供する。
- 子タスクを持つ親タスクの一覧上のサブタイトルには「完了数 / 全数 件のサブタスク完了」を表示する(子を持たない場合はメモの先頭行、無ければ優先度、それも無ければ「サブタスクなし」を表示)。
- 進捗集計(ヘッダーの完了率バー)は**リーフタスクのみ**を対象に「完了数 / 全リーフタスク数」で算出する。親タスク自体は分母・分子に含めない。

### 5.2 ステータス・優先度・進捗・期間・メモ・タグ

- ステータスは「未着手」「進行中」「完了」の3値。詳細パネルのステータスピッカーで変更する。
- ステータス変更時、進捗率(`progress`, 0〜100の10刻み)を自動補正する: 「完了」にすると100%、「未着手」にすると0%、「進行中」にした際に現在0%または未指定なら10%に補正する(それ以外はユーザーが手動で変更するまで維持)。
- 優先度は「高」「中」「低」「未設定」の4値。一覧のドロップダウンメニューまたは詳細パネルから変更できる。
- 期間(開始日・終了日)は入力任意。両方入力した場合、終了日が開始日より前であればエラー表示し保存を止める。
- メモは最大1,500文字、タスク名は最大30文字の入力上限を持つ。
- タグは自由入力(カンマ区切り、または個別入力してEnter)。同一タグの重複登録は不可。

### 5.3 検索・フィルタ・並び替え

- タスク名・メモ・タグを対象としたキーワード検索(部分一致、大文字小文字を区別しない)。
- ステータス、優先度、期限(すべて/期限切れ/期限あり/期限なし/期間指定)でフィルタできる。
- フィルタは親子関係を保ったまま適用する(子タスクが条件に一致すれば、条件に一致しない親タスクも表示上残す)。
- 並び替えは「追加順」(`order`フィールドの昇順)と「優先度順」(高→中→低→未設定)の2種から選択できる。並び替えを変更してもDBの`order`値自体は変更されない(表示上のソートのみ)。

### 5.4 一括追加・インポート/エクスポート

- テキストエリアに1行1タスクの形式で入力し、行頭のTabキー(インデント)でサブタスクの階層を表現できる一括追加機能を持つ。
- JSON形式・CSV形式でタスク一覧全体をエクスポートできる(階層構造を保持)。
- JSON・CSVファイルからタスクをインポートできる(既存タスクへの上書きではなく追加)。
- 一括追加・インポートいずれも、不正な行(タスク名が空等)はスキップし、有効なタスクのみ登録する。

### 5.5 ドラッグ&ドロップによる並び替え

- 「追加順」表示中かつフィルタ未適用の場合に限り、タスク行をドラッグ&ドロップで並び替えられる。
- 並び替えは**同一階層(同じ親を持つタスク同士)の間でのみ**行える。異なる親を跨いだ移動は行えない。
- 並び替え結果は`order`フィールドとしてDBに保存され、ページ再読み込み後も維持される。

### 5.6 削除・ゴミ箱

- タスクの削除は論理削除とし、削除したタスクの配下のサブタスクも連動して論理削除する。
- 削除直後はトーストに「元に戻す」アクションを表示し、即座に復元できる。
- 「削除済みタスク」ダイアログ(ゴミ箱)から、削除済みタスクの一覧確認・個別の復元・完全削除ができる。
- 完全削除は物理削除であり、元に戻せない(確認ダイアログを経由する)。
- 削除済みタスクの一覧には、削除日時と配下に含まれる削除済みサブタスクの件数を表示する。
- 進捗ダッシュボード機能のプロジェクトのような「保持期間」の概念は持たない(自動物理削除は行わないが、期限による自動整理も行わない。完全削除は常に手動)。

### 5.7 複製

- タスク(サブタスクを含む)を複製できる。複製されたルートタスクのタイトルには「のコピー」を付与し、複製直後はトーストから元に戻せる(完全削除で取り消す)。

## 6. 非機能要件

| 分類 | 要件 |
| --- | --- |
| データ整合性 | 論理削除されたタスクの子孫は連動して論理削除・復元する(親のみ復元して子が削除済みのまま、という不整合を避ける) |
| 入力上限 | タスク名30文字・メモ1,500文字の上限を明示し、超過分は自動的に切り詰める(一括追加・インポート含む全経路で統一) |
| 操作の取り消し | 追加・複製・一括追加・削除は、直後であればトーストの「元に戻す」から取り消せる |
| 既存資産との整合 | 既存のNext.js(App Router) + TypeScript + Tailwind CSS + shadcn/ui(Base UI) + Prisma(SQLite)の構成を踏襲する |
| 単一ユーザー前提 | ロールによる権限分離は行わない |

## 7. データモデル(実装済み)

- `Task`: id, title, status(not_started/in_progress/done), priority(1〜3、null許容), memo, startDate, endDate, progress(0〜100), tags(カンマ区切り文字列としてDB保存、UI上は配列), order, parentId(自己参照、`onDelete: Cascade`), deletedAt(論理削除日時), createdAt, updatedAt
  - 進捗ダッシュボード機能の各モデルとは無関係の独立したテーブル。
  - `parentId`の自己参照は`onDelete: Cascade`のため、親を物理削除すると子も連動して物理削除される(ただし本機能は論理削除を用いるため、物理削除はゴミ箱からの完全削除でのみ発生する)。

## 8. 技術方針

- ドラッグ&ドロップ: `@dnd-kit/core` + `@dnd-kit/sortable`(進捗ダッシュボード機能の`@dnd-kit/core`利用実績を踏襲し、階層内ソート専用に`@dnd-kit/sortable`を追加導入)。
- 階層データはDBでは`parentId`によるフラットな親子構造で保持し、サーバーで`buildTaskTree`によりツリー構造(`TodoTask.children`)へ組み立ててからクライアントへ渡す。
- バリデーションは進捗ダッシュボード機能と同様、外部ライブラリ(zod等)を使わずプレーンなTS関数で行う。
