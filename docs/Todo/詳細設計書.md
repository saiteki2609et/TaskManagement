export type ImportTaskInput = {

  startDate: string | null; endDate: string | null; progress: number;

ツリー操作用の純粋関数(いずれも`TodoTask[]`を受け取り新しい配列/値を返す。破壊的変更は行わない):

| 関数 | 概要 |
| --- | --- |
| `findTask(tasks, id)` | idに一致するノードを再帰探索。無ければ`null` |
| `findPath(tasks, id)` | ルートから対象ノードまでの祖先配列(パンくず用)。無ければ`null` |
| `replaceSiblingOrder(tasks, parentId, orderedSiblings)` | `parentId`(nullならルート)の子配列を丸ごと差し替える。ドラッグ&ドロップ後の楽観的更新・失敗時のロールバックに使用(3.2節) |
| `collectExpandableIds(tasks)` | 子を持つノードのid一覧(「すべて展開」用) |
| `countTasks(tasks)` | `{ total, done }`。**リーフタスクのみ**カウントし、子を持つノードは自身をカウントせず子の集計値をそのまま合算する |
| `sortTasksForDisplay(tasks, mode)` | 表示専用の並び替え。`mode === "priority"`のときのみ優先度順(未設定は最下位)に並び替え、`children`にも再帰適用。`"created"`のときは入力順のまま(=DBの`order`順) |
| `countBulkTasks` / `countImportTasks` | 一括追加・インポートのプレビュー件数算出 |
| `taskToImportInput(task)` | `TodoTask`→`ImportTaskInput`変換(エクスポート用) |

### 2.4 フィルタ(`src/components/todo/filters.ts`)

```typescript
export type StatusFilter = "all" | TaskStatus;
export type PriorityFilter = "all" | "none" | Priority;
export type DueFilter = "all" | "overdue" | "has" | "none" | "range";
export type TaskFilters = {
  search: string; status: StatusFilter; priority: PriorityFilter;
  due: DueFilter; dueFrom: string | null; dueTo: string | null;
};

export function isFiltersActive(filters: TaskFilters): boolean;
// search.trim()が空でない、またはstatus/priority/dueのいずれかがall以外

export function filterTaskTree(tasks: TodoTask[], filters: TaskFilters): TodoTask[];
// isFiltersActiveがfalseならtasksをそのまま返す(早期リターン)
// trueの場合、各ノードについて:
//   - 自身がtaskMatchesFiltersに合致 → そのまま採用(子はフィルタしない。配下全体を表示)
//   - 合致しない → 子孫を再帰フィルタし、1件でも残れば「自身のtitle等はそのまま・childrenだけ絞り込んだノード」として採用
//   - 子孫も0件なら除外
```

- `overdue`判定は`task.endDate < 今日の日付文字列 && status !== "done"`。時刻を持たない日付文字列同士の辞書順比較で判定する(`"YYYY-MM-DD"`形式であれば文字列比較=日付比較として成立する)。
- `range`判定は`dueFrom`/`dueTo`のいずれか一方のみ指定でも機能する(未指定側は無制限)。

### 4.2 `TodoView`

主なstate:

| state | 型 | 用途 |
| --- | --- | --- |
| `tasks` | `TodoTask[]` | サーバーから受領した生データ。Server Action成功後は戻り値で丸ごと置換 |
| `sortMode` | `SortMode` | 並び替え表示モード(既定`"created"`) |
| `selectedId` | `string \| null` | 詳細パネルの表示対象 |
| `expandedIds` | `Set<string>` | 展開中のノードid集合(既定は空=全折りたたみ) |
| `filters` | `TaskFilters` | 検索・フィルタ条件(既定は`DEFAULT_FILTERS`、全て非適用) |
| `addDialog` | `{ open: boolean; parentId: string \| null }` | タスク追加ダイアログの開閉+追加先(ルート or 特定タスクの子) |
| `deletedTasks` | `DeletedTaskSummary[]` | ゴミ箱ダイアログの表示データ(ダイアログを開いた時点で取得) |

導出値:
- `displayTasks = filterTaskTree(sortTasksForDisplay(tasks, sortMode), filters)`(`useMemo`)
- `dragEnabled = sortMode === "created" && !isFiltersActive(filters)`
- `selectedPath = selectedId ? findPath(tasks, selectedId) : null`(詳細パネルの表示要否とパンくずに使用)

ドラッグ&ドロップの処理は`TodoView`内の`handleDragEnd`が担う(3.2節参照。実際の`DndContext`/`SortableContext`は`SortableTaskList`側に切り出している)。

```typescript
function getSiblings(parentId: string | null): TodoTask[]; // parentId=nullならtasks、それ以外はfindTask(tasks, parentId)?.children

async function handleDragEnd(event: DragEndEvent) {
  // 1. active.id === over.id、またはoverが無ければ何もしない
  // 2. active/overそれぞれのdata.current.parentIdを比較し、異なれば何もしない(親を跨ぐ移動は禁止)
  // 3. 対象のsiblings配列からoldIndex/newIndexを求め、配列をsplice操作で並び替え
  // 4. setTasks(replaceSiblingOrder(prev, parentId, reordered)) で楽観的に反映
  // 5. reorderTasksAction(parentId, reordered.map(t => t.id)) を呼び、
  //    成功時はサーバーの最新ツリーで置換、失敗時はreplaceSiblingOrderで元のsiblingsに戻し toast.error
}
```

### 4.3 `SortableTaskList`(`src/components/todo/sortable-task-list.tsx`)

```typescript
type SortableTaskListProps = {
  tasks: TodoTask[]; selectedId: string | null; expandedIds: Set<string>;
  showActions: boolean; dragEnabled: boolean;
  onDragEnd: (event: DragEndEvent) => void;
  onSelect / onToggleExpand / onExpandSubtree / onCollapseSubtree /
  onDelete / onDuplicate / onChangePriority / onRequestAddChild: (...) => void;
};
```

- `useSensors(useSensor(PointerSensor, { activationConstraint: { distance: 4 } }))`で、4px未満の移動はドラッグと認識しない(クリック操作との誤認防止。進捗ダッシュボード機能のD&D実装と同じ閾値)。
- `DndContext`のルート直下に`SortableContext`(ルート階層の`items`)を配置し、`TaskListItem`が子を持つ場合は自身の内部でさらに`SortableContext`(その子階層の`items`)をネストする(4.4節)。
- `TodoView`から`ssr: false`の`next/dynamic`で読み込まれ、ロード中は「読み込み中...」を表示する。

### 4.4 `TaskListItem`(`src/components/todo/task-list-item.tsx`)

```typescript
type TaskListItemProps = {
  task: TodoTask; parentId: string | null; depth: number;
  selectedId: string | null; expandedIds: Set<string>;
  showActions: boolean; dragEnabled: boolean;
  onSelect / onToggleExpand / onExpandSubtree / onCollapseSubtree /
  onDelete / onDuplicate / onChangePriority / onRequestAddChild: (...) => void;
};
```

- `useSortable({ id: task.id, data: { parentId }, disabled: !dragEnabled })`。`attributes`/`listeners`は掴みハンドル(`GripVertical`アイコンの`<button>`)にのみ付与し、行全体はドラッグ起点にしない。
- 外側の`<div>`に`ref={setNodeRef}`と`style={{ transform: CSS.Transform.toString(transform), transition, opacity: isDragging ? 0.5 : 1 }}`を適用する(dnd-kit標準のトランスフォーム反映パターン)。
- 掴みハンドルは`dragEnabled`のときのみ描画する(無効時は要素ごと出さない。ホバー時のみ表示する挙動は採用していない=常時表示)。
- `depth`に応じて`marginLeft: depth * 18`(px)でインデントを表現する。
- 子ノードは`hasChildren && isExpanded`の場合のみ描画し、`SortableContext`(`items = task.children.map(c => c.id)`)でラップして自身の子階層を独立したソート単位にする。

### 4.5 `TaskDetailPanel`

- `draft state + isDirty比較`パターン(進捗ダッシュボード機能の`DeliverableCard`と同型)。`title`/`priority`/`memo`/`startDate`/`endDate`/`status`/`progress`/`tags`をそれぞれ`useState`で複製し、いずれか1つでも元の`task`と異なれば`isDirty = true`となり保存ボタンが活性化する。
- `path`(祖先タスクの配列)をパンくずとして描画し、末尾以外の祖先はクリックでその階層へ選択を移せる。
- ステータス変更(`handleStatusChange`)は`TaskDetailPanel`側でも同様の`progress`自動補正ロジックをクライアント側で先行適用し、保存前のプレビューに反映する(サーバー側`updateTaskAction`の補正ロジックと二重に持っているが、同じ規則で実装されているため不整合は生じない)。

### 4.6 `TaskFormDialog`

- `open`の変化を`prevOpen`との比較で検知し、開いた瞬間に全フィールドを初期値へリセットする(進捗ダッシュボード機能の各種フォームダイアログと同型の「render中に前回のopenと比較してリセットする」パターン)。
- メモ欄はタスク追加時点から入力可能(`memo`フィールドを`title`/`priority`/`startDate`/`endDate`/`tags`と同列で保持・送信する)。
