# Todo機能 機能仕様書

## 0. 本書について

- 本書は`/todo`画面の表示項目・操作・入力チェック・メッセージ文言を、実装に基づいて記録する。内部実装(型・関数・コンポーネント)は[Todo詳細設計書](./詳細設計書.md)を参照する。
- メッセージ文言は既存の実装文言をそのまま転記している。

---

## 1. 共通仕様

### 1.1 ヘッダーナビゲーション

[src/components/layout/header.tsx](../../src/components/layout/header.tsx)の`mainNavItems`のうち「Todo」(`/todo`)が本機能に対応する(`active: true`)。ナビゲーション表示順は「ダッシュボード → プロジェクト管理 → カレンダー → Todo」(Todoは末尾)。

### 1.2 メッセージ表示規約

- 成功時は`toast.success`、失敗時は`toast.error`。
- 追加・複製・一括追加・削除の直後は、成功トーストの`action`に「元に戻す」ボタンを付与する(1.3節)。
- Todo機能には業務ルール由来の動的エラー文言(名前重複等)は存在しない。すべて固定文言の`toast.error`で表現する。

### 1.3 「元に戻す」の実装方針

| 操作 | 元に戻す方法 | 備考 |
| --- | --- | --- |
| タスク追加 | 完全削除(`permanentlyDeleteTaskAction`) | 追加直後はまだ他の変更が積み重なっていない前提で、物理削除で取り消す |
| 一括追加 | 完全削除(`permanentlyDeleteTasksAction`、ルートID群を一括指定) | |
| タスク複製 | 完全削除(`permanentlyDeleteTaskAction`) | |
| タスク削除 | 復元(`restoreTaskAction`) | 削除は論理削除のため、物理的には残っている |

インポートには「元に戻す」を提供しない(件数が不定で、他の追加操作と混在しうるため)。

## 2. SCR-T01 Todo一覧・詳細

### 2.1 前提条件

- タスクが1件も無い場合、一覧エリアに「タスクがありません」を表示する。
- タスクは存在するがフィルタ条件に一致するものが無い場合も、一覧は空(0件)として表示される(専用の空状態メッセージは無い)。

### 2.2 表示項目一覧

| 項目 | データソース | 表示形式 | 空値時 |
| --- | --- | --- | --- |
| 見出し・日付 | クライアント側で算出 | 「今日のTodo」+「2026年9月8日(火)」形式 | - |
| 全体完了率 | `countTasks(tasks)`(リーフタスクのみ集計) | プログレスバー+「{done} / {total} 完了」 | タスク0件時は`0 / 0 完了` |
| タスク行(一覧) | `TodoTask`(表示順は2.6節) | 展開アイコン・ステータスアイコン・タイトル・サブタイトル・期間ラベル・タグ | 子タスク0件かつメモも優先度も無い場合「サブタスクなし」 |
| 詳細パネル | 選択中の`TodoTask` | パンくず+タイトル+ステータス/優先度/期間/タグ/メモの編集フォーム | 未選択時は非表示(一覧が全幅表示になる) |

### 2.3 一覧行の表示仕様

- ステータスアイコン: 完了は`Check`(塗りつぶし)、進行中は`CircleDot`、未着手は`Circle`。優先度が設定されている場合は優先度の色をアイコン背景に反映する(完了時は常にプライマリ色)。
- サブタイトルの決定順序: ① 子タスクを持つ場合「{完了数} / {全数} 件のサブタスク完了」 ② 子タスクが無くメモがあればメモの内容 ③ メモが無く優先度があれば「優先度: {ラベル}」 ④ いずれも無ければ「サブタスクなし」。
- 期間が設定されている場合、カレンダーアイコン+`M/D 〜 M/D`形式のラベルを表示する。
- タグが1件以上あれば、行下部にピル形式で一覧表示する。
- 行にホバー、または行内の要素にフォーカスすると、右側に操作アイコン(子タスク展開/折りたたみ・サブタスク追加・複製・優先度変更・削除)が表示される(常時は非表示。`showActions`が偽の場合はこの領域自体を無効化する)。
- ドラッグハンドル(掴みアイコン)は、ドラッグ&ドロップが有効な状態(2.7節)であれば**常に表示**する(ホバー時のみの表示ではない)。

### 2.4 操作仕様

| # | 操作 | 事前条件 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- | --- |
| 1 | 「+」(タスクを追加)押下→フォーム送信 | タスク名が空でない、期間が不正でない | `createTaskAction` | トースト「「{title}」を追加しました」(元に戻す付き)。追加タスクを選択状態にする | トースト「追加に失敗しました」 |
| 2 | 行の「サブタスクを追加」押下→フォーム送信 | 同上 | `createTaskAction`(`parentId`指定) | 同上。加えて親タスクを自動的に展開する | 同上 |
| 3 | 「テキストで一括追加」押下→送信 | 1件以上有効なタスク行がある | `createTasksBulkAction` | トースト「{count} 件のタスクを追加しました」(元に戻す付き) | トースト「一括追加に失敗しました」 |
| 4 | 行クリック | - | (Action呼び出しなし)`selectedId`を切替(同じ行を再クリックで選択解除) | - | - |
| 5 | 展開/折りたたみアイコンクリック | 子タスクを持つ | `expandedIds`をtoggle | - | - |
| 6 | 「すべて展開」/「すべて折りたたむ」 | - | `expandedIds`を子を持つ全ノード/空集合に一括設定 | - | - |
| 7 | 行の「子タスクをすべて展開/折りたたむ」 | 子タスクを持つ | 対象ノード配下のみ`expandedIds`を更新 | - | - |
| 8 | 並び替えメニューから「追加順」/「優先度順」選択 | - | `sortMode`を切替(再フェッチなし) | - | - |
| 9 | 検索欄への入力 | - | `filters.search`を更新。タスク名・メモ・タグを対象に部分一致(大小無視) | - | - |
| 10 | ステータス/優先度/期限フィルタの選択 | - | `filters`を更新 | - | - |
| 11 | 行の優先度メニューから選択 | - | `updateTaskAction(id, { priority })` | トースト「「{title}」の優先度を{ラベル}にしました」 | トースト「更新に失敗しました」 |
| 12 | 行の複製アイコン押下 | - | `duplicateTaskAction` | トースト「「{title}」を複製しました」(元に戻す付き) | トースト「複製に失敗しました」 |
| 13 | 行の削除アイコン押下→確認 | - | `AlertDialog`「タスクを削除しますか？」→OKで`deleteTaskAction` | トースト「「{title}」を削除しました」(元に戻す付き) | トースト「削除に失敗しました」 |
| 14 | 行のドラッグ&ドロップ | 2.7節の条件を満たす | `reorderTasksAction` | 一覧が新しい順序で表示される(トーストなし) | トースト「並び替えに失敗しました」。表示は元の順序に戻る |
| 15 | 詳細パネルでの編集→保存 | 2.5節のバリデーションを満たし、かつdirty | `updateTaskAction` | トースト「タスクを保存しました」 | トースト「保存に失敗しました」 |
| 16 | 詳細パネルの削除アイコン押下 | - | 13と同じ確認フロー | 同上 | 同上 |
| 17 | パンくずの祖先クリック | - | (Action呼び出しなし)`selectedId`を該当祖先に切替 | - | - |
| 18 | エクスポート(JSON/CSV) | - | クライアント側でファイル生成しダウンロード(Action呼び出しなし) | ファイルがダウンロードされる | - |
| 19 | インポート(JSON/CSV) | ファイルに1件以上有効なタスクが含まれる | `importTasksAction` | トースト「{count} 件のタスクをインポートしました」 | 解析0件時: トースト「インポートできるタスクが見つかりませんでした」。読み込み例外時: トースト「ファイルの読み込みに失敗しました」。Action失敗時: トースト「インポートに失敗しました」 |
| 20 | 「削除済みタスク」押下 | - | ダイアログを開き`getDeletedTasksAction` | 一覧表示 | トースト「削除済みタスクの取得に失敗しました」 |

### 2.5 バリデーション

| ケース | タイミング | 表示 |
| --- | --- | --- |
| タスク名が空 | 送信/保存押下時 | 送信・保存ボタンを`disabled`にする(追加ダイアログ・詳細パネルとも) |
| 終了日 < 開始日 | 入力変更時 | 「終了日は開始日以降の日付にしてください」を赤字表示し、送信・保存ボタンを`disabled`にする |
| タスク名の文字数上限(30文字) | 入力中 | `maxLength`属性で入力自体を制限。カウンタ「{現在の文字数} / 30」を表示 |
| メモの文字数上限(1,500文字) | 入力中 | 同上。「{現在の文字数} / 1500」 |

### 2.6 一覧の表示順

- 既定(「追加順」)は`order`フィールドの昇順(=DB上の並び順)。
- 「優先度順」を選択すると、高→中→低→未設定の順に並び替えて表示する(同一優先度内の相対順序は元の順序を保持。サブタスクにも再帰的に適用)。並び替えを変更してもDBの`order`値自体は変化しない。
- 検索・フィルタを適用している間は、一致したタスクを含む祖先チェーンのみが表示され、それ以外は除外される。

### 2.7 ドラッグ&ドロップによる並び替え仕様

- **有効条件**: 並び替えが「追加順」、かつ検索・フィルタが1つも適用されていない場合のみ有効。条件を満たさない間はドラッグハンドル自体を表示しない。
- **対象範囲**: 同じ親を持つタスク同士(兄弟)の間でのみ並び替え可能。異なる親の配下へドラッグしても何も起こらない。
- **操作**: 各行左端の掴みハンドル(常時表示)をドラッグし、目的の位置にドロップする。
- **保存**: ドロップ時にクライアント側で即座に表示順を更新したうえで`reorderTasksAction`を呼び出し、対象兄弟グループの`order`をまとめて更新する。失敗時は表示を元に戻し、トーストでエラーを通知する。

## 3. タスク追加ダイアログ

### 3.1 表示項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| タスク名 | 必須 | 最大30文字、文字数カウンタ表示 |
| 優先順位 | 任意 | 未設定/高/中/低のトグルボタン群 |
| 期間 | 任意 | 開始日・終了日(日付入力) |
| タグ | 任意 | Enter/カンマで確定、複数登録可 |
| メモ | 任意 | 最大1,500文字、文字数カウンタ表示 |

- サブタスク追加時はダイアログタイトルが「サブタスクを追加」になる(通常のタスク追加は「タスクを追加」)。
- ダイアログを開くたびに全フィールドが空の状態にリセットされる。

## 4. 一括追加ダイアログ

### 4.1 入力仕様

- テキストエリアに1行1タスクとして入力する。
- 行頭に**Tabキー**を入力すると、その数だけ階層が下がり、直前の(浅い方の)タスクのサブタスクとして扱われる。
- 入力例(ダイアログ内にプレースホルダとして表示):
  ```
  企画資料をまとめる
  	アジェンダを作成する
  	スライドを作成する
  		デザインを確認してもらう
  買い出しに行く
  ```
- リアルタイムに解析件数を「{count} 件のタスクが追加されます」(0件時は「タスク名を入力してください」)として表示する。
- タスク名は30文字を超える部分を自動的に切り詰める。空行はスキップする。

## 5. 削除済みタスク(ゴミ箱)ダイアログ

### 5.1 表示項目

| 項目 | データソース | 表示形式 |
| --- | --- | --- |
| タスク名 | `DeletedTaskSummary.title` | テキスト(優先度があればバッジを左に表示) |
| 削除日時 | `deletedAt` | 「M/D HH:mm に削除」 |
| 配下件数 | `descendantCount` | `0`超のとき「・{N} 件のサブタスクを含む」を併記 |

- 表示されるのは「削除済みルート」(自身が削除済みで、親がいない、または親が削除されていないタスク)のみ。削除済みの子は親の行に件数として集約される。
- 一覧0件時は「削除済みのタスクはありません」を表示。

### 5.2 操作仕様

| # | 操作 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | 「タスク一覧に戻す」押下 | `restoreTaskAction` | トースト「タスクをタスク一覧に戻しました」 | トースト「復元に失敗しました」 |
| 2 | 「完全に削除」押下→確認 | `AlertDialog`「完全に削除しますか？」→OKで`permanentlyDeleteTaskAction` | 一覧から即座に消える(完了トーストは無し) | トースト「完全な削除に失敗しました」 |

## 6. エクスポート/インポート

### 6.1 エクスポート

- ヘッダーの「エクスポート」ドロップダウンから「JSONでエクスポート」「CSVでエクスポート」を選択できる。
- ファイル名は`tasks-{YYYY-MM-DD}.json` / `tasks-{YYYY-MM-DD}.csv`。
- 階層構造をそのまま(JSON)、またはCSVの`level`列で表現して(CSV)、現在表示中ではなく**全タスク**(フィルタ非適用)を出力する。

### 6.2 インポート

- 「インポート」ボタンからファイル選択(`.json`/`.csv`)し、選択と同時に取り込みを開始する(確認ダイアログは無い)。
- JSON: オブジェクト単体でも配列でも受け付ける。不正なノードは除外し、有効なもののみ追加する。
- CSV: 1行目をヘッダーとして列名から値を取得する(列順は問わない)。ダブルクォートによるエスケープ・カンマ/改行を含む値に対応する。
- インポートは常に**追加**であり、既存タスクを上書き・重複排除することはない。

## 8. 受け入れ基準(チェックリスト)

### SCR-T01 Todo一覧・詳細
- [ ] タスクが1件も無い場合「タスクがありません」が表示される
- [ ] 完了率はリーフタスクのみを分母・分子として算出される(子を持つ親タスク自体はカウントされない)
- [ ] 「優先度順」表示中はドラッグハンドルが表示されず、並び替えできない
- [ ] フィルタ適用中はドラッグハンドルが表示されず、並び替えできない
- [ ] 「追加順」表示・フィルタ非適用時、ドラッグハンドルが常時表示される(ホバー無しでも見える)
- [ ] 同じ親を持つタスク同士のみドラッグで並び替えられ、異なる親を跨いだ移動は発生しない
- [ ] 並び替え結果はページ再読み込み後も保持される
- [ ] タスク削除後、トーストの「元に戻す」を押すと即座に一覧へ復帰する
- [ ] 終了日が開始日より前の場合、保存・追加ができない
- [ ] タスク名30文字・メモ1,500文字を超える入力は自動的に切り詰められる

### タスク追加ダイアログ
- [ ] メモ欄が表示され、入力した内容が作成したタスクに反映される
- [ ] サブタスク追加時はダイアログタイトルが「サブタスクを追加」になる

### 一括追加ダイアログ
- [ ] タブでインデントした行が正しくサブタスクとして登録される
- [ ] 空行・タスク名の無い行は無視される

### 削除済みタスクダイアログ
- [ ] 削除済みルートのみが一覧に表示され、その配下の削除済み件数が併記される
- [ ] 完全削除は確認ダイアログを経由し、取り消せない

### エクスポート/インポート
- [ ] JSON/CSVいずれの形式でも、階層構造を保ったままエクスポート・再インポートできる
- [ ] 不正な値を含むファイルをインポートしても例外にならず、安全な既定値に補正される
