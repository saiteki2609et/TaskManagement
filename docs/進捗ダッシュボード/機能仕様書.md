# プロジェクト進捗管理画面 機能仕様書

## 0. 本書について

- 本書は画面ごとの表示項目・操作・入力チェック・メッセージ文言・状態遷移を、実装・テストにそのまま利用できる粒度で定義する。要件の根拠は [要件定義書](./要件定義書.md)、内部実装(型・関数・コンポーネント)は [詳細設計書](./詳細設計書.md)を参照する。
- 画面IDは基本設計書・詳細設計書と共通(SCR-01〜05)。
- メッセージ文言は既存Todo機能([src/components/todo/todo-view.tsx](../../src/components/todo/todo-view.tsx))の「〜しました」「〜に失敗しました」というトーン・文体に合わせている。

## 1. 共通仕様

### 1.1 ヘッダーナビゲーション

[src/components/layout/header.tsx](../../src/components/layout/header.tsx)の`mainNavItems`を以下のとおり変更する。

| ラベル | href | 変更前 | 変更後 |
| --- | --- | --- | --- |
| ダッシュボード | `/dashboard` | `active`未指定(無効・ツールチップ「近日公開予定です」) | `active: true`相当(通常リンク化) |
| プロジェクト管理 | `/projects` | ラベル「プロジェクト」、`active`未指定 | ラベルを「プロジェクト管理」に変更し`active: true`相当(通常リンク化) |

ナビゲーション項目の表示順は「ダッシュボード → プロジェクト管理 → カレンダー → Todo」とする(Todoをカレンダーの後ろに配置)。カレンダーは本機能の対象外のため`active`状態は変更しない。

### 1.2 プロジェクト切替(`ProjectSwitcher`)

- 配置: `/dashboard`ページ上部(タブの上、プロジェクト完了率サマリの左)。
- 選択候補: アーカイブされておらず、かつ削除されていないプロジェクトのみ(`listSwitchableProjectsAction`)。
- 候補が0件の場合: セレクトの代わりに「プロジェクトがありません」というテキストと「プロジェクトを作成」ボタン(`/projects`へのリンク)を表示する。
- 選択変更時: 即座にURLクエリ`?project=<id>`を書き換え、選択中プロジェクトのデータを再取得して画面全体(現在表示中のタブ)を再描画する。タブ切替は保持する。
- URLの`project`パラメータが存在するがそのプロジェクトが存在しない/アーカイブ済み/削除済みの場合: 候補の先頭(作成日時が最も新しいもの)へ自動的にフォールバックする。

### 1.3 メッセージ表示規約

- 成功時は`toast.success`、失敗時は`toast.error`(既存Todo機能踏襲)。
- 「元に戻す(Undo)」操作を提供する場合は、成功トーストの`action`にボタンを埋め込む(例: 成果物削除時)。本機能で元に戻す操作を提供するのは「プロジェクトの論理削除」のみ(ゴミ箱からの復元操作で代替可能なため、削除直後のトースト上にUndoは設けない。理由: プロジェクト削除は確認ダイアログを経由する重い操作であり、既存Todo機能の「タスク削除」ほど頻発しないため)。
- 業務ルールエラー(プロジェクト名重複、成果物種類の使用中削除)は、詳細設計書 2.5節の`ActionResult`を分岐し、サーバーから返された具体的な文言をそのまま`toast.error`に表示する。

### 1.4 ステータス表示一覧

| 区分 | 値 | 表示ラベル | バッジ色 |
| --- | --- | --- | --- |
| 成果物ステータス | `not_started` | 未着手 | グレー |
| | `in_progress` | 進行中 | 青 |
| | `on_hold` | 保留 | 黄 |
| | `in_review` | レビュー中 | 紫 |
| | `done` | 完了 | 緑 |
| セル/機能行 集約ステータス | `not_applicable` | 対象外(-) | 淡グレー |
| | `partially_delayed` | 一部遅延 | 赤(強調) |
| | `done` | 完了 | 緑 |
| | `not_started` | 未着手 | グレー |
| | `in_progress` | 進行中 | 青 |

## 2. SCR-01 全体進捗ビュー

### 2.1 前提条件

- 選択中プロジェクトに`Phase`・`Feature`が1件も無い場合、マトリクス表は表示できない。「工程・機能が未登録です。まず工程・機能を登録してください」という空状態を表示し、工程・機能の追加UIへの導線を出す。

### 2.2 表示項目一覧

| 項目 | データソース | 表示形式 | 空値時 |
| --- | --- | --- | --- |
| プロジェクト全体完了率 | `projectCompletionSummary` | 「全体完了率: 42% (21/50)」 | 成果物0件時「対象データがありません」 |
| 工程別完了率(列ヘッダー) | `phaseCompletionSummary` | 「基本設計: 12/20 成果物 完了」 | セル同様「対象外」 |
| マトリクス行 | `Feature`(`order`昇順) | 機能名 | - |
| マトリクス列 | `Phase`(`order`昇順) | 工程名 | - |
| セル | `aggregateCellStatus` | バッジ+件数(例: 「進行中(2/5)」) | 0件時「-」(`not_applicable`) |
| 成果物種類パレット | `DeliverableType`(プロジェクト固有、`order`昇順) | バッジ一覧(横スクロール) | 0件時「成果物種類が未登録です」+マスタ管理への導線 |

### 2.4 バリデーション・確認ダイアログ

| ケース | タイミング | 表示 | OK時 | キャンセル時 |
| --- | --- | --- | --- | --- |
| ドロップ先工程がパレット項目の想定工程と不一致 | ドロップ直後(Action呼び出し前) | 確認ダイアログ「「{種類名}」の想定工程は「{想定工程名}」ですが、「{ドロップ先工程名}」に追加しようとしています。追加しますか?」 | 次の確認(重複チェック)へ進む、または直接追加 | 追加を中止(何も変更しない) |
| 同一セルに同一種類が既に存在 | ドロップ直後(工程不一致確認の後) | 確認ダイアログ「同じ種類の成果物が既に存在します。追加しますか?」 | 追加を実行 | 追加を中止 |

### 2.5 セル詳細パネル仕様

`CellDetailPanel`は「一覧画面」と「詳細編集画面」の2画面をダイアログ内で切り替える構成とする(ダイアログを閉じると一覧画面にリセットされる)。

**一覧画面**:
- 右上に表示形式トグル(リスト/グリッド、既定はグリッド)を表示する。成果物が0件の場合はトグル自体を非表示にする。
- リスト形式: テーブル(列: 名称/ステータス/担当者/期限)。`plannedEndDate`超過かつ未完了の行は赤みがかった背景で強調する。
- グリッド形式: カードレイアウト(2〜3列)。同じ項目(名称/ステータス/担当者/期限)を表示し、遅延時は赤系の枠線+背景で強調する。
- いずれの形式も、項目をクリックすると詳細編集画面に遷移する。
- パネル下部に「成果物種類を選択」プルダウン+「追加」ボタン(プルダウンによる代替追加。2.3節 操作3)を常設する。

**詳細編集画面**:
- ヘッダーに「←」戻るボタンを表示し、押下で一覧画面に戻る(表示形式の選択は保持される)。
- 表示項目: 成果物名(編集可)、ステータスピッカー(5値)、担当者(テキスト入力)、**リンク(URL、任意。入力済みの場合は隣に外部リンクアイコンボタンを表示し、新規タブで開ける)**、予定開始日/予定完了日、実績開始日/実績完了日、進捗率(ステータスが`in_progress`/`on_hold`/`in_review`のときのみスライダー表示。既存`TaskDetailPanel`のプログレス表示条件踏襲)、メモ、保存ボタン(dirty時のみ活性)、削除アイコン。
- `plannedEndDate`超過かつ未完了の場合、枠線を赤系にして強調する。

## 3. SCR-02 スケジュール(ガント)ビュー

### 3.1 前提条件

- 全体進捗ビューと同一プロジェクトの`Feature`/`Deliverable`データを用いる。`Feature`が0件の場合は2.1節と同じ空状態を表示する。

### 3.2 表示項目一覧

| 項目 | データソース | 表示形式 |
| --- | --- | --- |
| 表示単位切替 | クライアントstate | セグメントボタン「週/月」(四半期は廃止) |
| ページング | クライアントstate(`anchor`) | 「◀/▶」ボタン+範囲ラベル(週表示: 「9/6 - 12」形式、月表示: 「2026年9月」形式)+「今日」ボタン(`anchor`を本日にリセット) |
| 横軸の日付目盛り | クライアントstate(`GanttScale`) | 2段構成。1段目に月(月が変わる列にのみ表示)、2段目に日を表示。**いずれも左揃え**(バーの左端がどの日から始まっているか目視で数えやすくするため)。週表示は直近1週間(7列)、月表示は直近1か月(その月の日数分の列)のみを表示する |
| 機能フィルタ / 工程フィルタ | クライアントstate | セレクト(「全て」を既定値とする) |
| 機能行(折りたたみ時) | `Feature` | ドラッグハンドル(常時表示)+機能名+遅延件数バッジ(例: 「発注機能(遅延2件)」。0件時はバッジ非表示) |
| 成果物行(展開時) | `Deliverable` | ドラッグハンドル(常時表示)+成果物名+予定バー+実績バー |
| 予定バー | `plannedStartDate`〜`plannedEndDate` | 半透明の背景バー。日付未設定の場合はバー非表示、行に「予定日未設定」を薄字で表示。表示中の週/月の範囲外にかかる部分は表示範囲の境界で切り取られる |
| 実績バー | `actualStartDate`〜`actualEndDate`または`progress` | ステータス色で塗りつぶし。遅延中(`isDelayed`)は赤枠で強調 |

### 3.3 操作仕様

| # | 操作 | 処理 | 備考 |
| --- | --- | --- | --- |
| 1 | 表示単位切替(週/月) | クライアント側で列幅・目盛り粒度を再計算。`anchor`(基準日)はそのまま維持し、その日を含む週/月の表示に切り替える | 再フェッチなし |
| 2 | 「◀」「▶」ボタン押下 | `anchor`を週表示なら7日、月表示なら暦月単位で前後にずらして表示範囲を切り替える | 再フェッチなし。範囲外のバーは自動的に切り取られる |
| 3 | 「今日」ボタン押下 | `anchor`を本日にリセット | 再フェッチなし |
| 4 | 機能行クリック | `expandedFeatureIds`をtoggle | 初期状態は全機能が折りたたみ(要件定義書 9章確定事項) |
| 5 | 機能/工程フィルタ変更 | クライアント側でdeliverables配列をfilter | 再フェッチなし |
| 6 | 成果物バー(または成果物行)をクリック | 2.5節と同じ「詳細編集画面」をダイアログ表示。ステータス・担当者・日付・進捗・メモ・リンクをその場で編集できる | 保存・削除は本ビューの成果物一覧にも即時反映される |
| 7 | 機能行のドラッグハンドルをドラッグ&ドロップ | `reorderFeaturesAction`で`Feature.order`を更新 | 全体進捗ビューのマトリクス行の並び順にも反映される(共有フィールドのため)。失敗時はトースト「並び替えに失敗しました」を表示し元の並びに戻す |
| 8 | 成果物行のドラッグハンドルをドラッグ&ドロップ | 同じ機能の中(同一階層内)でのみ並び替え可能。`reorderDeliverablesAction`で`Deliverable.order`を更新 | 他の機能配下へはドラッグできない(機能をまたいだ並び替えは不可)。失敗時はトースト「並び替えに失敗しました」を表示し元の並びに戻す |

### 3.4 画面状態

- 予定日・実績日が両方とも未設定の成果物は、バーを描画せず行のみ表示する(0件と誤認されないよう成果物名は必ず表示する)。
- 表示中の週/月の範囲に予定日・実績日が一切かからない成果物は、バーが表示範囲外に切り取られるため見た目上は「予定日未設定」の行と区別がつかない(ページングで該当期間まで移動すればバーが現れる)。

## 4. SCR-03 設計書QA機能

### 4.1 前提条件

- プロジェクトの`designDocFolderPath`が未設定(空文字)の場合、QAタブ全体を「設計書フォルダが未設定です。プロジェクト管理画面から設定してください」という案内に差し替え、チャット入力を無効化する。

### 4.2 表示項目一覧

| 項目 | データソース | 表示形式 |
| --- | --- | --- |
| 再取り込みボタン | - | ボタン(実行中は`disabled`+スピナーアイコン+文言「取り込み中…」) |
| 最終取り込み日時 | `listDesignDocumentsAction().lastScannedAt` | 「最終取り込み: 2026-09-05 10:20」。未実行時「未実行」 |
| 未取り込み警告 | `pendingCount` | `pendingCount > 0`の場合のみ黄色警告バー「未取り込み/インデックス未反映の設計書が{N}件あります」 |
| **参照している設計書一覧** | `listDesignDocumentsAction().documents` | サイド欄にタイトル+取込状態バッジ(未取込/更新中/取込済/失敗)のリスト。件数を見出しに表示(例:「参照している設計書(8)」)。**設計書フォルダのサブフォルダ構成をそのまま階層(ツリー)表示する**(フォルダ名を見出し行として挟み、配下のファイルをインデント表示。フォルダはファイルより先に、フォルダ同士・ファイル同士は名前順に並べる) |
| チャット履歴(本文) | `askQuestionAction`/`listQaHistoryAction` | 質問・回答を吹き出し形式で表示 |
| 参照元 | `answer.sources` | 回答直下にチップ形式「{ドキュメント名} > {セクション名}」を複数表示。クリックでポップオーバー展開し、ファイルパス+抜粋(`snippet`)を表示 |
| 質問入力欄 | クライアントstate | テキストエリア+送信ボタン(空文字時`disabled`) |
| 履歴一覧(サイド) | `listQaHistoryAction` | 質問文+日時のリスト、クリックで本文にスクロール/再表示。履歴が1件以上ある場合のみ見出し右にゴミ箱アイコン(履歴クリアボタン)を表示 |

### 4.3 操作仕様

| # | 操作 | 事前条件 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- | --- |
| 1 | 「再取り込み」押下 | 実行中でない | `rescanDesignDocumentsAction` | トースト「取り込みが完了しました(追加{added}件・更新{updated}件・削除{removed}件・失敗{failed}件)」。`failed > 0`の場合は`toast.warning`相当(赤字ではなく黄字)で失敗ファイル名を併記 | トースト「取り込みに失敗しました」(想定外の例外時のみ。ファイル単位の失敗は上記に含める) |
| 2 | 質問送信 | 入力欄が空でない、かつ`asking`でない | `askQuestionAction` | チャットに回答+参照元を表示。入力欄クリア | トースト「回答の生成に失敗しました」。チャットにエラー行「回答を生成できませんでした。再度お試しください」を残す |
| 3 | 参照元チップをクリック | - | `Popover`でドキュメント名・セクション名・ファイルパス・抜粋(`snippet`)を表示(Action呼び出しなし。回答生成時に取得済みの情報を表示するのみ) | - | - |
| 4 | 履歴一覧から過去の質問をクリック | - | Action呼び出しなし。チャット本文側の対応するメッセージ要素まで`scrollIntoView({ behavior: "smooth" })`でスクロールし、1.5秒間リング枠でハイライト表示する(再送信はしない) | - | - |
| 5 | 設計書一覧から取込済みの項目をクリック | `indexStatus === "indexed"`(未取込/更新中/失敗の項目はクリック不可) | `getDesignDocumentChunksAction(documentId)`でセクションごとの抽出内容を取得しダイアログ表示 | ダイアログにセクションラベル+本文を一覧表示 | トースト「設計書の内容取得に失敗しました」 |

### 4.4 画面状態

| 状態 | 表示 |
| --- | --- |
| 初期表示(履歴0件) | 「まだ質問がありません。設計書について質問してみましょう」という空状態+入力欄 |
| 回答生成中 | 直近の質問吹き出しの下に「回答を生成しています…」のローディング表示(要件定義書 6章「可用性」対応) |
| 取り込み中 | ボタン`disabled`+スピナー。**設計書一覧はファイル単位で「更新中」(スピナー付き水色バッジ)→「取込済」(緑バッジ)へリアルタイムに遷移する**(SSEで即時反映。4.5節参照)。フォルダから移動・削除されたファイルの項目は一覧から消える(4.5節) |

### 4.5 設計書一覧のリアルタイム進捗更新(実装補足)

- 再取り込み実行中、クライアントは`GET /api/design-documents/{projectId}`(Route Handler)にSSE(`EventSource`)で接続し、設計書一覧の状態を最新化する。接続直後に現在の一覧を1回受信し、以降はサーバー側で状態が変化するたびに最新の一覧がpushされる。
- **Server Action(`listDesignDocumentsAction`)ではなく通常のRoute Handlerを使う理由**: Next.jsは同一クライアントからのServer Action多重呼び出しを直列化するため、実行中の「再取り込み」アクション(数十秒かかりうる)が完了するまでポーリング用Server Actionの送信自体が待機されてしまう。Route Handler経由の`fetch`/`EventSource`はこの制約を受けないため、再取り込み中でも独立して進捗を取得できる。
- サーバー側(`scanAndIndex`)は、各ファイルの抽出・埋め込み処理を開始する前に`indexStatus`を`processing`に更新してから処理を行う(2段階書き込み)。これにより、処理中のファイルが1件ずつ「更新中」として観測できる。
- **一定間隔のポーリングではなくSSEにした理由**: 当初は1秒間隔のポーリングだったが、Ollamaのembeddingは1件目のみモデルロードで時間がかかり2件目以降は短時間(1秒未満のことが多い)で完了するため、ポーリングでは2件目以降の「更新中」表示を取りこぼす不具合が判明した。そのため、状態が変化した瞬間にサーバー側からpushするSSE方式に変更した(プロセス内イベントバス`progress-bus.ts`経由)。
- **フォルダ移動・削除への追随**: 再取り込みのたびに、DB上の各設計書レコードについて実ファイルの存在を確認し、存在しなければレコードを削除する(一覧からも消える)。これにより、設計書フォルダの再編(サブフォルダへの移動等)後に旧パスの項目が一覧に残り続ける、といった状態を防ぐ。

## 6. マスタ管理共通仕様

工程(`Phase`/`GlobalPhase`)・機能(`Feature`)・成果物種類(`DeliverableType`/`GlobalDeliverableType`)は、権限分離を設けず利用者全員が編集可能(要件定義書 4章)。

### 6.1 工程・機能マスタ(全体進捗ビューからアクセス)

| # | 操作 | 処理 | 成功時 | 失敗時 |
| --- | --- | --- | --- | --- |
| 1 | 追加 | 名称入力(空文字不可)→`createPhaseAction`/`createFeatureAction` | トースト「「{name}」を追加しました」 | トースト「追加に失敗しました」 |
| 2 | 名称編集 | インライン編集→`updatePhaseAction`/`updateFeatureAction` | トースト「更新しました」 | トースト「更新に失敗しました」 |
| 3 | 削除 | `AlertDialog`「「{name}」を削除しますか?この工程/機能に紐づく成果物もすべて削除されます」→OKで`deletePhaseAction`/`deleteFeatureAction` | トースト「「{name}」を削除しました」 | トースト「削除に失敗しました」 |
| 4 | 工程を共通マスタから追加(「マスタから追加」ポップオーバー) | 共通工程マスタ(`GlobalPhase`)のうち、当該プロジェクトに未追加(同名の`Phase`が存在しない)の項目を候補として一覧表示。チェックボックスで複数選択、または「全選択」→`addGlobalPhasesToProjectAction(projectId, ids)` | トースト「工程を追加しました」。候補が0件の場合は「追加できる項目がありません」を表示 | トースト「追加に失敗しました」 |

機能(`Feature`)は共通マスタを持たないため、操作4に相当する機能は無い(要件定義書 3章の用語定義どおり、機能はプロジェクトごとに個別定義する前提のため)。このマスタ管理画面自体にはドラッグによる並び替えは提供しない(登録順を`order`として保持するのみ)。機能はスケジュール(ガント)ビューの機能行からドラッグ&ドロップで並び替えられる(3.3節操作7。工程にはこの並び替え手段は無い)。成果物(`Deliverable`)も同ビューの成果物行から、同じ機能の中(同一階層内)に限りドラッグ&ドロップで並び替えられる(3.3節操作8)。

| # | 操作 | 処理 | 成功時 | 失敗時 |

新規プロジェクト作成時は、共通工程マスタ・共通成果物種類マスタの内容がそれぞれ`Phase`・`DeliverableType`へ初期コピーされる(6.1節・6.2節の「マスタから追加」操作で、既存プロジェクトへも個別に取り込み可能)。

## 8. 受け入れ基準(画面別チェックリスト)

### SCR-01 全体進捗ビュー
- [ ] セル内に1件でも遅延成果物があれば、他がすべて完了でもセルが「一部遅延」表示になる

- [ ] 工程不一致のドロップで警告が出て、キャンセルすると成果物が追加されない
- [ ] 同一セルへの同一種類の再ドロップで確認が出て、OKで2件目が追加される
- [ ] D&Dできない操作(プルダウン追加)でも同じ確認フローを通る
- [ ] セル詳細パネルでリスト/グリッド表示を切り替えられ、どちらの形式でも項目クリックで詳細編集画面に遷移する
- [ ] 詳細編集画面でリンクを入力すると外部リンクアイコンが表示され、新規タブで開ける
- [ ] 「マスタから追加」で、共通マスタのうち当該プロジェクトに未追加の項目のみが候補として表示される

### SCR-02 ガントビュー
- [ ] 初期表示で成果物行がすべて折りたたまれている
- [ ] `plannedEndDate`を1日でも超過し未完了の成果物バーが赤強調される(猶予日数なし)
- [ ] 機能行の「遅延N件」が配下成果物の`isDelayed`件数と一致する
- [ ] 週表示・月表示とも、横軸1段目に月、2段目に日付の目盛りが刻まれる(四半期表示は選択肢に存在しない)
- [ ] 週表示は直近1週間(7日分)、月表示は直近1か月分のみが表示される

- [ ] 成果物行のドラッグハンドル以外の部分をクリックしたときは、並び替えではなく詳細編集画面が開く

- [ ] 回答に必ず参照元(ドキュメント名+セクション)が1件以上併記される(根拠なしで回答しない)

### SCR-04/05 プロジェクト管理
- [ ] 削除済み(ゴミ箱内)のプロジェクトと同名では新規作成できない
